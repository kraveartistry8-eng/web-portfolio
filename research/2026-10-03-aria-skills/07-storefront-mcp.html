01

What it actually is

Shopify's agents documentation is organised as a buyer journey in four stages: negotiate and authenticate, with agent profile verification and access tiers; discover products, through a global catalogue or a single merchant's Storefront Catalog; build carts and convert to checkout, through Cart and Checkout MCP tools; and monitor orders, through Order MCP tools and webhook subscriptions.

The Storefront Catalog MCP sits at https://{storedomain}/api/ucp/mcp and implements the Universal Commerce Protocol. It exposes exactly three tools: search_catalog, lookup_catalog and get_product. Every request must include a meta.ucp-agent.profile URL pointing at the agent's profile. It is catalogue only; cart and purchase live elsewhere in the stack.

The theme side of this is the standard storefront events and actions layer shipped on 17 June. Themes emit events such as shopify:cart:lines-update, and Shopify.actions exposes functions an app or agent can call. Shopify is explicit that this is recommended rather than required, because every action ships with a default implementation on every Liquid storefront.

02

Does the claim hold

Substantially yes, and my own first read was too harsh. Looking only at the catalogue endpoint, "add to cart and purchase" is wrong. Looking at the agents documentation as a whole, Cart, Checkout and Order MCP tools are all there, so the claim describes the stack accurately.

The word doing the most work is "autonomously", and the caveat is that the Universal Cart API is described as an early access program. Treat the catalogue half as shipped and the transacting half as real but early.

03

The devil's advocate

  1. No incumbent is the whole point, and also the whole risk

    Nobody in the $5M to $20M band has bought this, which is why there is no supplier to displace. It is also why there is no evidence it produces revenue. Those are the same fact seen from two sides.

  2. Default implementations undercut the pitch, slightly

    Actions work on every Liquid storefront without setup. So "an agent can drive your store" is already partly true for a merchant who does nothing. The honest pitch is about doing it well, with events that fire correctly and a catalogue an agent can actually parse, rather than about possibility.

  3. This is the one place to hold the line on numbers

    Agentic traffic is new enough that nobody has credible conversion data. Your plan already says to say what you built and what it does, and to attach no revenue number. That discipline matters more here than anywhere else on this list, because the temptation is largest.
