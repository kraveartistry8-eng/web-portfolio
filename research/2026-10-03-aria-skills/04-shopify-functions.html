01

What it actually is

Functions customise Shopify's backend logic. You write code that Shopify injects at a defined function target, it receives JSON input and returns JSON output, and that output directs what Shopify does. It runs server side, on Shopify's infrastructure, not in the browser.

They are written in Rust or JavaScript and compile to WebAssembly modules. shopify.dev recommends Rust for performance, specifically to prevent failures on large carts. JavaScript has templates and libraries and is the faster path to a first working Function.

The available targets cover discounts, payment customisation, delivery options, cart and checkout validation, order routing, product bundles, fulfilment constraints, local pickup and pickup points. That list is effectively the set of commercial rules a merchant might want to bend.

Scripts, the Shopify Plus feature Functions replaces, was deprecated on 30 June 2026. Anything still published was deactivated and stopped working. Shopify's own migration path is to install an app built on Functions, or rebuild the logic yourself.

02

Does the claim hold

Yes. "Replaces deprecated Scripts" and "sub-5ms backend execution" both check out, the latter from Shopify's own migration page, which describes Functions executing in under five milliseconds against Scripts.

"Rust/Wasm" is half the story. Wasm is correct and mandatory. Rust is recommended rather than required, and leaving JavaScript out of the row makes the skill look several weeks further away than it is.

03

The devil's advocate

  1. The commercial window is three months old and closing

    Scripts died on 30 June. Merchants who cared have already installed a Functions-based app. What remains is the slower half: stores running generic app behaviour where bespoke logic used to be, or running nothing. That is still a real gap in October, and it is more diagnosable than most openings, but it is not getting larger.

  2. JavaScript is enough until it is not

    Shopify recommends Rust for large carts for a reason. If you sell a discount rebuild to a merchant with a big catalogue and heavy carts, a JavaScript Function is where it will fail, and it will fail in the checkout, which is the worst place to learn this.

  3. Functions are a sandbox, not a server

    The input and output contract is the whole interface. If a rule depends on outside data, that is a different architecture. shopify.dev does not document network access on the Functions overview, so scope any Function that needs external data carefully until you have checked.
